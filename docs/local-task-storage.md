# Локальное хранилище задач

`lib/local/tasks-store.ts` — клиентский API. При импорте база не открывается; функции открывают её только при вызове. Наличие UI или авторизации не подразумевает наличия локальной копии.

База `flowstate-local`, версия 2 (переход с версии 1 сохраняет записи): хранилище `tasks` с составным ключом `[user_id, task_id]` и индексом `by_user`. Запись содержит `task` с явно перечисленными полями Supabase и отдельный объект `metadata` с необязательным `localUpdatedAt`. Индексы, ключи и схема должны обновляться через новую версию базы; никогда не уничтожайте хранилище при обновлении. Дата дедлайна остаётся строкой `YYYY-MM-DD`. UUID задачи создаётся вызывающим кодом один раз и передаётся повторно без изменений.

`putTask(userId, task, metadata?)`, `getTask(userId, taskId)`, `getTasksByUser(userId)` и `deleteTask(userId, taskId)` возвращают Promise. Запись завершается успешно только после фиксации транзакции. Ошибки представлены `LocalTaskStoreError` с кодами `invalid`, `unavailable`, `blocked`, `quota` и `database`. `deleteTask` удаляет только локальную запись указанного пользователя и не является командой удаления на сервере.

Вызывающий код обязан получить идентификатор из проверенной сессии, передавать его при каждой операции и сбрасывать отображаемые данные при смене пользователя. API не проверяет личность и не является защитой от другого кода или человека с доступом к тому же профилю браузера. IndexedDB не шифрует данные и может очищаться браузером. Не храните токены, пароли и ключи. При выходе данные автоматически не удаляются; политика очистки должна быть определена отдельно.

Метаданные не должны передаваться в Supabase. Добавлено хранилище `outbox` с отдельным составным ключом пользователя и операции. `queueTaskChange` атомарно сохраняет задачу и операцию или tombstone; `mergeServerTasks` не заменяет записи с ожидающими операциями. Автоматической синхронизации нет, состояния `pending` и `uncertain` не подтверждают запись на сервере. Интерфейс Tasks использует очередь для задач, созданных локально; автоматической отправки нет. При дальнейшей реализации очередь должна отдельно хранить владельца, стабильный ID операции и задачи, вид изменения и необходимые данные версии; удаление должно быть явной операцией, а не выводиться из отсутствия локальной записи. Подтверждение сервера, идемпотентность и конфликты потребуют отдельного проектирования. Чтение привязано к подтверждённому пользователю, действующий онлайн CRUD сохранён.

## Проверка в браузере

Запустите `npm run dev` и откройте `/dev/local-storage-test` в Firefox. Страница доступна только в development и использует фиксированные тестовые UUID, не связанные с реальным аккаунтом. Кнопками создайте, покажите, измените и удалите тестовую задачу; после обновления страницы снова нажмите «Показать локальные задачи». В инструментах разработчика Firefox откройте «Хранилище» → Indexed DB → `flowstate-local` → `tasks` и проверьте составной ключ и содержимое записи. Страница не перезаписывает уже существующую запись при создании и изменяет или удаляет только запись с ожидаемыми тестовыми маркерами. Другие локальные данные она не удаляет.

После успешной загрузки списка `/tasks` сохраняет серверные задачи в локальный кеш. Набор `npm run test:local-tasks` использует эмуляцию IndexedDB и не заменяет браузерную проверку.


Для сохранения намерения перед сетевым запросом, подтверждения результата, упорядочивания операций и безопасной реакции на смену сессии требуется дальнейшая работа. Текущий Tasks поддерживает только ограниченный локальный CRUD для задач, созданных локально.

## Чтение на странице Tasks: FLOW-23.2a

Сервер подтверждает пользователя через Supabase Auth `getUser()` и загружает все страницы задач с фильтром по его ID. Только полный успешный список отправляется в `mergeServerTasks`; пустой успешный список тоже считается ответом сервера. Частичный результат при ошибке отбрасывается. Транзакция проверяет outbox и не перезаписывает записи с операциями `pending` или `uncertain`, включая tombstone. Отсутствующие в серверном ответе локальные записи не удаляются: локальный список может содержать устаревшие или уже удалённые на сервере задачи.

Если запрос задач не удался, клиент читает кеш исключительно для подтверждённого сервером пользователя. При отсутствии видимых записей показывается сообщение об отсутствии кеша; отдельный маркер успешно сохранённого пустого снимка пока не ведётся. Ошибки IndexedDB не скрывают успешный серверный ответ и отображаются отдельно при неудачном чтении. Данные на экране явно отмечены как локальные и потенциально устаревшие. При последующем успешном серверном ответе записи обновляются, но автоматически не удаляются.

Клиент слушает события Supabase Auth. При выходе, отсутствии сессии или смене ID он немедленно скрывает рабочее пространство и сбрасывает список; асинхронные результаты старой загрузки игнорируются. Локальные записи при выходе не удаляются. Данные из IndexedDB не подтверждают личность. Если Auth недоступен при открытии страницы и `getUser()` не может подтвердить пользователя, сервер направляет на вход и локальный кеш не открывается. Поэтому это не полноценный офлайн-вход: для него потребуются отдельно спроектированные проверка личности и срока действия доступа без сети, защита и политика хранения данных на общем устройстве, отзыв доступа и безопасная смена аккаунта. Без таких решений нельзя считать сохранённый ID или неподтверждённую локальную сессию авторизацией.

## Ограниченный локальный CRUD: FLOW-23.2b

При недоступности загрузки задач можно создать локальную задачу с UUID и затем изменять её поля, статус и удалять. Каждое действие фиксируется атомарно с отдельной операцией в outbox; локальное удаление создаёт tombstone. Новые операции получают монотонный номер в транзакции, старые операции могут не иметь номера и требуют отдельной обработки. После commit интерфейс показывает число операций и ожидающие задачи. После успешной серверной загрузки локальные ожидающие изменения и tombstone накладываются поверх ответа, а очередь не отправляется.

Для серверных задач локальное изменение и удаление пока отключены, в том числе для старых ожидающих операций без локального create или операций `uncertain`. Текущий онлайн CRUD не записывает намерение до сетевой отправки; ответ может потеряться после выполнения на сервере. Другой клиент также может изменить серверный снимок. Без согласованной версии записи и надёжного протокола подтверждения нельзя безопасно выводить порядок и результат таких изменений из кеша. Автоматического fallback или повтора после неясного ответа нет. Доступны обычные онлайн-операции над задачами без ожидающих изменений. При ошибке IndexedDB операции блокируются: иначе нельзя надёжно проверить очередь. Web Locks сериализует операции интерфейса разных вкладок одного профиля; при отсутствии API изменения недоступны. Проверка актуальности локального снимка отклоняет устаревшие изменения другой вкладки.

FLOW-23.3 потребует надёжного сохранения намерения до сетевой операции, серверного подтверждения, идемпотентности, обработки неопределённого результата и конфликта версий, политики удаления устаревших записей и модели полного снимка. Автоматическая синхронизация и её разрешение конфликтов сейчас не реализованы.

## Имитация ошибки чтения для ручной проверки

При `npm run dev` на странице `/tasks` доступна панель «Диагностика чтения задач». Ссылка «Включить» открывает `/tasks?simulateTaskError=1`, а «Выключить» возвращает на `/tasks`. Режим действует только для этого адреса и по умолчанию выключен. Переход на другой адрес без параметра отключает имитацию; в production параметр игнорируется, панель не показывается.

Сервер сначала вызывает обычный Supabase Auth `getUser()`. Только после успешной проверки диагностический режим возвращает ошибку чтения списка задач, не выполняя запрос списка. Остальные запросы и настройки не подменяются. Имитация сама по себе только включает обычный fallback; действия пользователя могут изменить локальную задачу и outbox. Сначала откройте `/tasks` с рабочим Supabase, чтобы сохранить задачи, затем включите имитацию и проверьте локальный список, предупреждение, недоступность редактирования серверных задач и доступность создания локальной задачи. После выключения проверьте серверную загрузку. Если кеша нет, отобразится сообщение об отсутствии сохранённых задач.

## Проект синхронизации FLOW-23.3a

Проект RPC, модели версий, идемпотентности, очереди и развёртывания описан в [task-sync-protocol-flow23-3a.md](./task-sync-protocol-flow23-3a.md). Это проект: реальной отправки outbox нет, SQL-заготовки не применялись и не готовы к развёртыванию. Прямой онлайн CRUD до будущего согласованного перехода сохраняет риск неизвестного результата запроса.

Проект с учётом подтверждённой схемы описан в [FLOW-23.3b](./task-sync-flow23-3b-design.md); миграция и RPC не готовы к применению.
